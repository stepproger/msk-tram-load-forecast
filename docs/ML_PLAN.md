## 1. Где на самом деле сидит метрика

| Факт (проверено бэктестом) | Число | Вывод |
|---|---|---|
| Медианный профиль `маршрут × тип дня × час` за последние 4 недели → следующий месяц | **WAPE-score 0.91–0.92** на стабильных периодах | Порог 0.88 (10 баллов) достигается простым профилем, **если уровень угадан** |
| То же, но с идеально известными дневными суммами (оракул) | 0.925–0.936 | **Потолок ≈ 0.93**: около 7% — почасовой шум (сбои, «пачки» вагонов), его никакая модель не уберёт |
| Тот же профиль из августа → сентябрь–октябрь (смена сезона) | **0.79**, смещение −16% | **Главный риск — уровень (сезон и тренд), а не форма суток** |
| Сетка из 36 вариантов оценщика (окна, медиана/среднее, группировка дней) | разброс 0.905–0.916 | Тюнинг оценщика даёт максимум около 1 п.п. Лучше всего: форма за 4 недели, уровень за 2 недели, медиана, 5 типов дней (Пн / Вт–Чт / Пт / Сб / Вс) |
| Праздники относительно воскресенья (1, 2, 8, 9 мая, 12–13 июня) | 0.83–1.16, в среднем около 1.0 | Праздник и перенесённый выходной = **воскресный профиль × 1.0** |
| Сокращённые предпраздничные дни (7.03, 30.04, 11.06) | 0.98–1.05 | Считаем обычным днём |
| Школьные каникулы (4–12.10, 21.02–1.03) | эффекта нет (±1%) | **Не делаем**. В абляции пишем честно: «проверено, эффекта нет» |
| Будни: февраль → март → сентябрь → октябрь | 237 → 253 тыс., 231 → 245 тыс. в день | Зимний уровень ≈ октябрьскому; тренд растущий. Априори ноябрь–декабрь ≈ октябрь × 1.00–1.03 |

## 3. Решение

```
ŷ(r, d, h) = Level(r, тип_дня(d)) × Shape(r, тип_дня(d), h) × Season(месяц) × Special(d) × Net(r, d) × Weather(d, h)
```
- **Level** — медиана дневных сумм за последние 2 «чистых» недели октября; **Shape** — медианные доли часов за 4 недели.
- **Season** — два скаляра (ноябрь, декабрь): априори 1.01, затем калибруем по лидерборду.
- **Special** — календарь из §2; **Net** — события сети из §2.
- **Weather** — LightGBM на отношении `y / базовый_прогноз` с признаками погоды (Open-Meteo, ERA5) и календаря. Даёт «ML-часть», доказательство эффекта погоды (абляция, критерий 2) и коэффициенты для ползунков UI. В финальный прогноз входит только если бэктест показывает прирост.
- **Интервалы q10/q90** — эмпирические квантили отношения `y / ŷ` на бэктесте, по часам.

## 4. Чего НЕ делаем (и почему)

| Идея | Почему нет |
|---|---|
| LSTM / TFT / N-BEATS / трансформеры | 10 месяцев × 9 рядов; потолок 0.93 уже почти достигнут профилем |
| Prophet / ARIMA по рядам | Годовую сезонность из 10 месяцев не выучить; недельную и суточную профиль уже покрывает |
| Лаги короче 61 дня | На тесте их нет — утечка. Лаги ≥ 61 дня попадают на лето и вредят |
| Обучение GBM «в лоб» на абсолютном target с признаком месяца | Не экстраполирует ноябрь и декабрь; ошибка уровня останется |
| Работа с 60 млн сырых строк ради метрики | `labels` достаточно. Сырые данные нужны только продукту (вагоны в час, пассажиры по картам) |
| Остановочная детализация ради метрики | Не оценивается. Для UI хватит эвристики `stop_shares` |
| Школьные каникулы как признак | Проверено: эффекта нет |
| Почасовые пробки | Открытой истории нет; в последнюю очередь (прокси или TomTom) и только ради критерия 2 |
| Пробинг лидерборда по маршрутам (вытаскивать суммы эталона) | Серая зона, эксплойт метрики. Калибруем только 2–4 глобальных скаляра |
